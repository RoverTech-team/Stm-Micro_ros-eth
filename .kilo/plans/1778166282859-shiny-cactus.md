### 3. High-Resolution Clock Implementation

**H7-Arm `InitHighResolutionClock()`** (lines 143-158):
```c
static void InitHighResolutionClock(void) {
  telemetry_cycles_per_us = SystemCoreClock / 1000000U;
  if(telemetry_cycles_per_us == 0U) {
    telemetry_cycles_per_us = 1U;
  }
  telemetry_cycles_per_ms = telemetry_cycles_per_us * 1000U;
  
  CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;  // Enable trace
#if defined(DWT_LAR)
  DWT->LAR = 0xC5ACCE55U;  // Unlock DWT
#endif
  DWT->CYCCNT = 0U;  // Reset cycle counter
  DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;  // Enable cycle counter
}
```

**H7-Arm `GetMonotonicTimeUs()`** (lines 160-186):
```c
static uint64_t GetMonotonicTimeUs(void) {
  uint32_t tick_ms_before, tick_ms_after, cycle_count;
  do {
    tick_ms_before = HAL_GetTick();
    cycle_count = DWT->CYCCNT;  // Read DWT cycle counter
    tick_ms_after = HAL_GetTick();
  } while(tick_ms_before != tick_ms_after);  // Ensure no tick rollover
  
  if(telemetry_cycles_per_ms == 0U) {
    return ((uint64_t)tick_ms_before) * 1000ULL;
  }
  
  uint32_t sub_ms_us = (cycle_count % telemetry_cycles_per_ms) / telemetry_cycles_per_us;
  return (((uint64_t)tick_ms_before) * 1000ULL) + (uint64_t)sub_ms_us;
}
```
Uses DWT cycle counter for microsecond-precision timing within milliseconds.

**Micro_ros_eth `InitHighResolutionClock()`** (lines 98-102):
```c
static void InitHighResolutionClock(void) {
  /* Renode does not emulate DWT cycle counting reliably for this target.
   * Keep the timing source simple and valid under emulation. */
  // EMPTY - no DWT initialization
}
```

**Micro_ros_eth `GetMonotonicTimeUs()`** (lines 104-112):
```c
static uint64_t GetMonotonicTimeUs(void) {
  if(osKernelGetState() == osKernelRunning) {
    return ((uint64_t)osKernelGetTickCount()) * 1000ULL;  // Millisecond precision only
  }
  return ((uint64_t)HAL_GetTick()) * 1000ULL;
}
```
Uses FreeRTOS tick count (millisecond precision) - no DWT cycle counter.

**Key Difference**: H7-Arm uses DWT cycle counter for microsecond timing (real hardware). Micro_ros_eth uses FreeRTOS tick count (millisecond precision) for Renode compatibility.

## Primary Architectural Differences

1. **Dual-Core Communication**: H7-Arm implements CM4/CM7 shared memory with cache coherency; Micro_ros_eth has no inter-core communication.

2. **Timing Precision**: H7-Arm uses DWT cycle counter for microsecond timing (required for real-time control); Micro_ros_eth uses millisecond tick count (sufficient for simulation).

3. **System Complexity**: H7-Arm is a complete robotic control system with sensors, actuators, and telemetry; Micro_ros_eth is a minimal heartbeat demo for Renode validation.

4. **Task Architecture**: H7-Arm uses multiple concurrent tasks for parallel processing; Micro_ros_eth uses minimal tasking.

5. **Hardware Abstraction**: H7-Arm directly accesses peripherals (DWT, cache, GPIO); Micro_ros_eth abstracts these for portability.

## Conclusion

The H7-Arm `main.c` is a **production-ready embedded control system** for a dual-core STM32H7 robot with real-time constraints, sensor fusion, and joint control. The Micro_ros_eth `main.c` is a **simulation-friendly demo** that validates micro-ROS connectivity over Ethernet in Renode without hardware-specific features.

The differences reflect their distinct purposes: one is designed for **real hardware deployment** with performance and precision requirements; the other for **development and testing** in an emulated environment with portability constraints.
